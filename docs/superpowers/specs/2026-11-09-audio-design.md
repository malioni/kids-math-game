# Audio — Design Spec

## Context

GitHub issue #8. The game has no sound, though `DESIGN.md` says icons, animation **and sound** carry all
meaning, because children aged 4–7 can't rely on reading. This adds feedback sounds and a quiet background
loop in every world and the menu, with placeholder sounds generated in code (as the placeholder art is) at
their final file names so real sounds can replace them later.

Agreed with the user on 2026-11-09:

- Placeholder sounds are generated by a headless tool, not downloaded or supplied.
- One quiet background loop per world, plus one for the menu.
- Two toggles in the level picker (the grown-up's area): background sound and effects, saved between
  sessions.
- Approach: an `AudioManager` autoload that plays sounds by name, triggered from `WorldBase`, the menu and
  the HUD in response to signals. Mechanics never touch audio.

## Goals

- Every right answer, wrong answer, placed or removed piece, finished difficulty and UI tap makes a sound.
- Background loops play in every world and the menu, crossfading between them and continuing across level
  changes inside a world.
- A grown-up can turn background sound and effects off separately, and the game remembers.
- A sound problem never crashes, stalls or blocks the game. A missing sound is caught by a test, not in
  play.
- A new world gets the shared sounds with no code, and adds only its own files.

## Non-goals

- Final, professionally made sounds (a later swap under the same file names).
- A sound when a piece bounces back, ticks while the picnic deals, or world-specific extras such as a river
  splash. Each is one call to add later.
- A volume slider, a "tap to start" screen, or native Android/iOS audio work.
- A game-wide event bus. When a second system needs to react to the same moments as audio (adaptive
  difficulty or a parent view), introduce a game-events autoload that `WorldBase` reports to, and have
  `AudioManager` listen to it. Until then, direct calls are simpler.

## Sounds

Names map to files: `<name>` → `res://assets/audio/<name>.wav`.

| Name | When | Triggered by |
|---|---|---|
| `win` | Right answer | `WorldBase._on_correct()` |
| `lose` | Wrong answer: a soft, friendly thud, never harsh | `WorldBase._on_incorrect()` |
| `complete` | The star screen appears | `WorldBase`, where it shows the star screen |
| `tap` | A button or card tap in the menu, picker or star screen | `MainMenu`, `LevelHud` |
| `<world>/place` | A piece goes in (plank, bag, fruit) | `WorldBase`, from `Mechanic.piece_placed` |
| `<world>/remove` | A piece comes out, or a balloon pops | `WorldBase`, from `Mechanic.piece_removed` |
| `<world>/ambience` | Background loop while in that world | `WorldBase._ready()` |
| `menu/ambience` | Background loop on the menu | `MainMenu._ready()` |

`<world>` is a world id from `GameRegistry.WORLDS`: `forest`, `sky`, `market`, `picnic`.

## Components

### `AudioManager` (autoload, `scripts/autoloads/audio_manager.gd`)

Registered after `SaveManager`, which it reads at startup.

- `play_sfx(name: String) -> void` plays an effect on the Effects bus. Effects use a small pool of players
  (6), taken in turn, so quick sounds overlap instead of cutting each other off.
- `play_music(name: String) -> void` plays a loop on the Music bus. The same name as the current loop does
  nothing. A different name crossfades over 0.5 s using two players. Loops are played quieter than effects.
- `set_music_enabled(enabled: bool)` / `is_music_enabled() -> bool`, and the same for effects. Each mutes
  its bus and saves the setting.
- `expected_sounds() -> Array[String]`: the shared names plus `ambience`, `place` and `remove` for every
  registered world, plus `menu/ambience`.
- Signals `sfx_played(name)` and `music_changed(name)`, emitted when a sound actually starts, so tests can
  check behaviour without audio output.
- Streams are loaded on first use and cached. Background loops are set to loop when loaded, so the generated
  files don't need special import settings.

### Audio buses (`default_bus_layout.tres`)

`Master` with two children, `Music` and `Effects`. The toggles mute a bus with
`AudioServer.set_bus_mute()`.

### `SaveManager`

`save_music_enabled()` / `load_music_enabled()` and `save_effects_enabled()` / `load_effects_enabled()`,
stored in the `meta` section and defaulting to on. An invalid value loads as on.

### `Mechanic`

Two new signals, emitted only when the player moves a piece, never on `setup()` or `reset()`:

- `piece_placed`: `PlacementMechanic` when a plank lands on the bridge; `MarketMechanic` when a bag lands on
  the table; `SharingMechanic` when fruit lands on the fox's plate.
- `piece_removed`: the same three when a placed piece is tapped back; `BalloonPopMechanic` when a balloon
  pops.

### `WorldBase`

- `_ready()`: plays `<world>/ambience` and connects `piece_placed` / `piece_removed` to `<world>/place` and
  `<world>/remove`.
- `_on_correct()`: plays `win`. `_on_incorrect()`: plays `lose`. Showing the star screen plays `complete`.

### `MainMenu` and `LevelHud`

- `MainMenu._ready()` plays `menu/ambience`. Play, Shuffle and card taps play `tap`.
- `LevelHud`: the badge, picker buttons (levels, Easy/Hard, the new toggles, shuffle, close, home) and
  star-screen buttons and cards play `tap`.
- Two new picker buttons in `ModeRow`, after Easy/Hard: a music note (background sound) and a speaker
  (effects), at least 100 px, highlighted when on and drawn crossed out when off. They call
  `AudioManager.set_music_enabled()` / `set_effects_enabled()` directly, since they don't affect the world.

### Placeholder sounds (`tools/make_audio_placeholders.gd`)

A headless tool, run like the other `tools/make_*` scripts, that synthesises every sound in
`expected_sounds()` and saves it with `AudioStreamWAV.save_to_wav()`: 22,050 Hz, mono, 16-bit.

- `win`: a short rising chime. `complete`: a longer flourish. `lose`: a soft, low, rounded thud.
- `tap`: a short soft click. `place`: a short knock, different in pitch per world. `remove`: a lighter
  click, except `sky/remove`, which is a pop.
- Loops of about 8 s, with the end blended into the start so they repeat without a gap: filtered noise for
  the forest river and the sky wind, a soft murmur for the market, simple chirps for the picnic, and a calm
  slow tone for the menu.

The four toggle icons (music on/off, effects on/off) are added to `tools/make_mode_icons.gd`, which
already draws the picker's other mode icons and has the drawing helpers, into `assets/sprites/ui/`.

## Error handling

- Unknown name or a file that won't load: `push_warning` once per name, then stay silent. No crash, no
  waiting.
- A sound never blocks game flow: nothing awaits a sound finishing.
- Web: browsers keep audio locked until the first tap. Godot resumes audio on that tap, so the menu loop
  starts then. Nothing else is needed.
- Headless tests and CI use Godot's silent audio driver. Behaviour is checked through the signals, so
  nothing depends on hearing output.

## Testing (GUT, tests written first)

- `tests/test_audio_manager.gd`:
  - Every name in `expected_sounds()` has a file that loads; adding a world without its sounds fails this.
  - `play_sfx` emits `sfx_played`. An unknown name emits nothing and doesn't crash.
  - `play_music` emits `music_changed`; the same name again doesn't; a new name does.
  - Each toggle mutes and unmutes its bus, and survives `SaveManager.reload()`.
- `tests/test_save_manager.gd`: the two settings default to on, round-trip, and reject invalid values.
- Each mechanic's test: `piece_placed` / `piece_removed` fire on the player's moves and not on `setup()` or
  `reset()`; a balloon pop fires `piece_removed`.
- World tests: right and wrong answers play `win` and `lose`; placing plays `<world>/place`; loading a
  world plays its ambience; changing level inside a world doesn't change the music.
- `tests/test_level_hud.gd` and `tests/test_main_menu.gd`: taps play `tap`; the toggles flip their setting
  and their look.

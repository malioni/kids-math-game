# PLAN.md — World 3: The Market (multiplication with bags of produce)

> GitHub issue: not filed. Design agreed with the user in conversation (2026-10-15).

## Feature
A new Market world where a customer orders an amount of produce (e.g. 12 tomatoes) and the child drags equal-sized bags (e.g. bags of 4) from never-ending crates onto a table, then presses Go; the customer celebrates if every ordered amount is matched exactly, otherwise throws a tomato and the child retries.

---

## Scope

**Included:**
- `DragPiece` base class holding the press/drag/tap/bounce logic now in `plank_drag.gd`; `PlankDrag` and the new `BagDrag` both extend it (no behaviour change for planks)
- `BagDrag`: a bag showing its size as a number plus an icon of its item
- `MarketMechanic`: one order slip (amount + icon per item), one crate per ordered item that never runs out, a table with one row per item, a Go button; emits `correct` / `incorrect`
- `MarketPuzzleGenerator`: builds orders from per-level ranges with the world's RNG
- `scripts/worlds/market.gd` (extends `WorldBase`) + `scenes/worlds/market/market.tscn`: customer, celebrate and throw-tomato reactions, retry prompt, `LevelHud`
- 20 level JSON files + `levels.json` in `data/levels/world_market/`
- Registration in `GameRegistry` (third world, after sky)
- Placeholder art generated by a headless GDScript tool, documented in a README
- DESIGN.md and `data/levels/README.md` updates
- GUT tests for every new script and the level data

**Out of scope:**
- Running total of placed items (deliberately never shown — the child multiplies)
- Distractor crates (only ordered items get a crate)
- The "cash register" (groups → total) round type — possible later
- Adaptive difficulty, audio, final art
- Persisting the generated puzzle across restarts (resume regenerates, as in other worlds)

## Design decisions

| Decision | Choice | Why |
|---|---|---|
| Infinite crate | Each crate holds one "ready" bag. When it's dropped on the table it becomes placed and the crate spawns a new ready bag. A drop anywhere else bounces back | Reuses the existing drag/bounce code; no special "spawn on press" input path |
| Where a bag lands | Anywhere over the table; it snaps to the end of its own item's row | Positioning isn't the math; one row per item keeps groups readable |
| Remove | Tap a placed bag → it tweens back to its crate and is freed | Same gesture as tapping a placed plank |
| Row cap | `max_bags_per_row` = 12; a 13th bag bounces back | Lets the child overshoot the answer (max 10) without unbounded layouts |
| Crowded rows | Spacing = `min(bag_width + gap, row_width / count)` so bags overlap once a row is full | Fits 12 bags in a row on a 1280-wide viewport |
| Bag label | Number + item icon texture (no emoji) | Godot's default font has no emoji glyphs; "no reading required" |
| Order check | `correct` only if, for every ordered item, placed bags × bag size == ordered quantity | One customer, one Go, every item must be right |
| Item visuals | The mechanic receives an `item_icons: Dictionary` (item id → Texture2D) export set in the world scene | Mechanic stays world-agnostic; "tomato" is just a data key to it |
| Bag sizes & counts | Stored per item in each level JSON | Level content lives in `data/` |
| Retry vs. reload | Retry clears the table and keeps the puzzle; loading a level generates a new one | Matches forest/sky |
| Throw | A tomato sprite tweens from the customer toward the table, growing, then a splat shows for 0.6 s, then the retry prompt | "Customer throws a tomato" — gentle, funny, no penalty |

## Implementation Steps

### 1. Extract `DragPiece` — `scripts/mechanics/drag_piece.gd`, `scripts/mechanics/plank_drag.gd`
- `class_name DragPiece extends Node2D`. Move from `plank_drag.gd`: signals `dropped`, `tapped`; constants `BOUNCE_DURATION`, `MOVE_DURATION`, `DRAG_Z_INDEX`, `TAP_THRESHOLD`; vars `interactive` (with setter), `is_placed`, `home`, and the private drag state; methods `_ready` (sets `home`), `_unhandled_input`, `bounce_back`, `move_to`, `cancel_drag`, `is_dragging`, `_begin_press`, `_end_press`, `_tween_to`, `_pointer_global`.
- The base expects two children: `Body` (a `Control`) and `Shadow` (a `CanvasItem`), shown only while dragging. Hit test: `_contains_global_point()` uses `Body.get_rect()` grown by `_touch_padding()` (virtual, returns `Vector2.ZERO` by default).
- `PlankDrag extends DragPiece` keeps `length`, `PLANK_HEIGHT`, `TOUCH_PADDING`, `configure()`, `get_width()`, and overrides `_touch_padding()` to return `TOUCH_PADDING`.
- Verify: `test_plank_drag.gd` and `test_placement_mechanic.gd` pass unchanged.

### 3. `BagDrag` — `scripts/mechanics/bag_drag.gd`, `scenes/mechanics/bag_drag.tscn`
- `class_name BagDrag extends DragPiece`. Scene: `Shadow` (TextureRect, `bag_shadow.png`, hidden, offset +4,+8), `Body` (TextureRect 96×96, `bag.png`, centred), `Body/SizeLabel` (Label, font 34, same colours as the plank label), `Body/Icon` (TextureRect 40×40 under the number). All `mouse_filter = 2`.
- Vars: `item: String`, `bag_size: int`.
- `configure(item_id: String, size: int, icon: Texture2D) -> void` sets both vars, label text and icon texture.
- `get_width() -> float` returns `Body.size.x`.
- `_touch_padding()` returns `Vector2(6, 6)`.

### 4. `MarketPuzzleGenerator` — `scripts/mechanics/market_puzzle_generator.gd`
- `class_name MarketPuzzleGenerator extends RefCounted`.
- `static func generate(params: Dictionary, rng: RandomNumberGenerator) -> Array[Dictionary]`: for each entry of `params["items"]` in order, `bag_size = rng.randi_range(bag_size.min, bag_size.max)`, `bag_count = rng.randi_range(bag_count.min, bag_count.max)`, returns `{"item", "bag_size", "bag_count", "quantity": bag_size * bag_count}`.
- No retries needed: every pick is valid by construction; ranges are validated by the level-data tests.

### 5. `MarketMechanic` — `scripts/mechanics/market_mechanic.gd`, `scenes/mechanics/market_mechanic.tscn`
- Signals: `correct`, `incorrect`, `bags_changed(item: String, count: int)`.
- Exports: `item_icons: Dictionary` (String → Texture2D), `go_texture: Texture2D`, `table_rect: Rect2 = Rect2(-380, -165, 760, 330)` (local), `row_y: Array[float] = [-100.0, 0.0, 100.0]` (local, top to bottom), `row_left: float = -350.0`, `row_right: float = 350.0`, `crate_x: float = 470.0`, `bag_gap: float = 12.0`, `max_bags_per_row: int = 12`.
- Scene children: `Table` (NinePatchRect at `table_rect`), `Crates` (Node2D), `PlacedBags` (Node2D), `ReadyBags` (Node2D), `Leaving` (Node2D — bags tweening back to their crate after a tap; not counted), `OrderSlip` (TextureRect 200×230, `order_slip.png`, at local (−620, −310)) with `OrderSlip/Lines` (VBoxContainer, 3 lines of ~60 px), `GoButton` (TextureButton 120×120 at local (410, 170)).
- With the mechanic at world position (670, 420) (Step 6) the global rectangles are, all inside 1280×720: HUD badge 20–220 × 10–96 (existing); order slip 50–250 × 110–340; customer 80–240 × 360–580; table 290–1050 × 255–585 with rows at y 320 / 420 / 520 and bags spanning x 320–1020; crates (150×110) centred at x 1140 → 1065–1215, in line with the rows; Go button 1080–1200 × 590–710. Nothing overlaps.
- `setup(orders: Array[Dictionary]) -> void`: stores orders (each needs `item`, `bag_size`, `quantity`) and calls `reset()`.
- `reset() -> void`: frees placed and ready bags and crates; rebuilds the order slip (one HBox per order: Label with the quantity, font 44, + 52×52 icon); for order *i* places a crate sprite at `(crate_x, row_y[i])` and spawns a ready bag on it; emits `bags_changed(item, 0)` for each order.
- `confirm() -> void`: `correct` if every order's `get_placed_count(item) * bag_size == quantity`, else `incorrect`.
- `set_interactive(enabled: bool) -> void`: Go button disabled + alpha 0.4 like placement; sets `interactive` on every bag.
- `get_placed_count(item: String) -> int`, `get_placed_total(item: String) -> int` (count × bag size; for tests/world, never displayed), `get_orders() -> Array[Dictionary]`, `get_placed_bags(item: String) -> Array[BagDrag]`, `get_ready_bag(item: String) -> BagDrag`.
- Drop handling: if the release point is inside `table_rect` (in global space) and the row has fewer than `max_bags_per_row` bags → mark placed, reparent to `PlacedBags`, relayout that row, spawn a new ready bag on the crate, emit `bags_changed`. Otherwise `bounce_back()`.
- Tap handling: only placed bags react. Remove from the row (relayout), tween it to its crate with `move_to`, then `queue_free()` after `DragPiece.MOVE_DURATION`; emit `bags_changed`. Removed bags are excluded from counts immediately (reparent to a `Leaving` node).
- Row layout: bag *k* of *n* at `x = row_left + bag_w/2 + k * step`, `step = min(bag_w + bag_gap, (row_right - row_left - bag_w) / max(n - 1, 1))`; later bags get higher `z_index` so overlaps read left to right.
- Rows are assigned by order index, so a 1-item level uses only the top row; crates sit in line with their row.

### 6. Market world — `scripts/worlds/market.gd`, `scenes/worlds/market/market.tscn`
- Scene (1280×720 play area): `Background` (Sprite2D `bg_market.png`, centred at (640, 360)), `Customer` (AnimatedSprite2D at (160, 470), animations `idle` loop, `celebrate` loop, `throw` once, 8 fps, from the placeholder sheets), `MarketMechanic` instance at (670, 420) with `item_icons` = tomato/potato/carrot textures and `go_texture` = `go_icon.png` (the order slip then sits above the customer as its speech bubble), `FlyingTomato` (Sprite2D `icon_tomato.png`, hidden), `Splat` (Sprite2D `splat.png`, hidden, at the table centre), `CelebrationParticles` (GPUParticles2D like forest), `RetryPrompt/RetryIcon` (same as forest), `LevelHud` (instance of `level_hud.tscn`).
- Script, following `sky_balloons.gd`: connects `correct`/`incorrect`/retry in `_ready()` before `super()`; `_world_id()` returns `"market"`; `_setup_level(level)` hides retry/tomato/splat, plays `idle`, calls `MarketPuzzleGenerator.generate(level, _rng)` → `_mechanic.setup(...)`, `set_interactive(true)`.
- `_on_correct()`: disable mechanic, play `celebrate`, restart particles, wait `celebrate_duration`, `_advance()` (with the `_load_count` guard).
- `_on_incorrect()`: disable mechanic, play `throw`, await `animation_finished`, tween `FlyingTomato` from the customer's hand to the splat position (0.5 s, scale 0.6 → 1.6, rotating), hide it, show `Splat` for 0.6 s, then show the retry prompt and return the customer to `idle`. Guard every await with `_load_count`.
- `_on_retry_pressed()`: hide retry and splat, `_mechanic.reset()`, `set_interactive(true)`.
- Public for tests: `@export var throw_duration: float = 0.5`, `@export var splat_duration: float = 0.6`.

## Data Changes

### Level file schema (`world_market`)

```json
{
  "id": "world_market_11",
  "world": "market",
  "mechanic": "market",
  "items": [
    { "item": "tomato", "bag_size": { "min": 1, "max": 3 },  "bag_count": { "min": 2, "max": 3 } },
    { "item": "potato", "bag_size": { "min": 4, "max": 6 },  "bag_count": { "min": 2, "max": 3 } },
    { "item": "carrot", "bag_size": { "min": 7, "max": 10 }, "bag_count": { "min": 2, "max": 3 } }
  ],
  "narrative_key": "market_11",
  "skill_tags": ["multiplication", "equal-groups"]
}
```

| Field | Type | Description |
|---|---|---|
| `items` | Array | One entry per ordered item, in row order (1–3 entries) |
| `items[].item` | String | `tomato`, `potato` or `carrot` (key into the mechanic's `item_icons`) |
| `items[].bag_size.min/max` | int | Inclusive range for how many items one bag holds. Tomato 1–3, potato 4–6, carrot 7–10 |
| `items[].bag_count.min/max` | int | Inclusive range for how many bags the answer takes; 2–10 |

### Difficulty table

Bag sizes are always the item's full range (tomato 1–3, potato 4–6, carrot 7–10). Every item in a level uses the same `bag_count` range.

| Level | Items | bag_count |

| 2 | tomato | 2–4 |
| 3 | tomato | 3–5 |
